# 五级流水线离散事件 CPU 模拟器

本项目使用 C++17 构建一个单发射、顺序执行的五级流水线模拟器。模拟时间由 CPU 和内存共享的全局离散事件队列推进，支持以下循环：

```asm
Loop:
    fld     f0, 0(x1)
    fadd.d  f4, f0, f2
    fsd     f4, 0(x1)
    addi    x1, x1, 8
    bne     x1, x2, Loop
Halt:
    halt                    # 模拟器扩展指令，不是标准 RISC-V 指令
```

程序对每个数组元素执行 `element += f2`。`x1` 指向当前元素，`x2` 是数组末尾的排他地址。测试程序默认处理两个元素。

## 模拟约定

- 地址为 32 位；数据内存按字节编址，每个 cell 为 8 位。`fld`/`fsd` 传输 8 个字节，要求 8 字节对齐。
- 指令使用枚举和结构化字段保存，不编码为机器码；为了体现取指 PC，按 4 字节的 RISC-V 指令地址步进。
- 内存内部把指令映射和数据字节映射分开保存，但共用 32 位模拟地址空间；代码和数据地址不能重叠。
- 整数寄存器为 32 个 32 位寄存器，`x0` 恒为 0；浮点寄存器为 32 个 64 位寄存器。
- `fadd.d` 使用 C++ `double` 运算；内存以小端字节顺序保存其 64 位表示。
- `Halt:` 是标签。模拟器增加了一条自定义 `halt` 指令，并在它到达 WB 时退休、停止模拟。
- `bne` 在 EX 阶段解析。顺序取指路径上已进入 IF/ID 的年轻指令会被冲刷；取指请求带 epoch，旧路径的迟到响应会丢弃。

## 全局事件队列

事件按 `(模拟时间, 阶段优先级, 插入序号)` 排序。同一模拟时刻先处理外部事件（包括内存请求到达和响应），再处理 CPU 时钟沿。因此响应恰好落在时钟沿时，CPU 能在该沿看到响应，行为不依赖事件先插入队列的顺序。

每个 CPU 时钟沿会先把响应邮箱中的内容应用到对应 IF 或 MEM 槽，再完成到期的 EX 工作，然后基于当前状态计算阶段 `done`、`canAccept` 和 `willMove`。流水线从 WB 向 IF 计算背压，所有槽位写入 `next` 状态后统一提交。空槽可以接收指令；满槽只有在本沿离开时才能接收新指令。

访存请求有唯一 `requestId`，响应回调只把响应放入 CPU 邮箱。Load 在 MEM 查询自己的邮箱项并等待数据；Store 在 MEM 发起一次写请求并等待确认。数据相关则由 ID 每个时钟沿重新检查：向 EX、MEM、WB 中寻找最近的较早写入者，若结果尚未有效就停顿；ID 读出的操作数快照随指令进入 ID/EX，EX 再用 MEM/WB 旁路值覆盖快照中的旧值。未就绪的较近生产者会遮蔽更早的生产者，避免误用旧值。

## 流水线职责

| 阶段 | 工作 |
|---|---|
| IF | 按 PC 请求指令，并等待取指响应 |
| ID | 解码、读取寄存器堆、确定源/目的寄存器、检查 RAW 数据相关 |
| EX | 地址计算、整数/浮点运算、分支比较与目标判定 |
| MEM | Load/Store 访存并等待各自请求的响应 |
| WB | 更新整数或浮点寄存器并退休指令 |

模型采用弹性单槽级间寄存器。MEM 等待较慢响应时会产生背压；空的 EX 槽仍可暂存一个独立的年轻指令，填满后背压才继续传向 ID/IF。每个槽保存动态指令序号和 PC，因此同一个 `Loop` 地址在多次迭代中仍能区分不同动态实例。

## 延迟配置

```sh
./build/simulator
./build/simulator --elements 8 --addend 0.25
./build/simulator --elements 4 --cycle 3 --cpu-to-memory 1 --memory-to-cpu 2 --add 5
```

参数单位为整数纳秒：

- `--elements N`：数组元素数，范围 1 至 10,000。
- `--addend X`：写入浮点寄存器 `f2` 的加数。
- `--cycle N`：CPU 时钟周期，必须大于零。
- `--cpu-to-memory N`：请求链路延迟。
- `--memory-to-cpu N`：响应链路延迟。
- `--add N`：`fadd.d` 和 `addi` 的 EX 运算延迟。

默认时钟周期 2 ns，请求和响应链路各 2 ns，EX 算术延迟 1 ns。它们是教学模型参数，不是特定处理器的测量值。

## 当前范围

这是顺序、单发射的教学模型，没有缓存、分支预测、乱序执行或虚拟内存地址转换。内存服务时间为 0 ns，CPU/Memory 链路延迟分别建模；内存可并行接受事件请求，不模拟端口仲裁。IF 每次最多保留一个取指请求。指令以结构化对象存放，不模拟机器码译码。
