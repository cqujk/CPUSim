# 八级流水线离散事件 CPU 模拟器

本项目使用 C++17 构建一个单发射、顺序执行的八级流水线模拟器。模拟时间由 CPU 和内存共享的全局离散事件队列推进，支持以下循环：

```asm
Loop:
    fld     f0, 0(x1)
    fadd.d  f4, f0, f2
    fsd     f4, 0(x1)
    addi    x1, x1, 8
    bne     x1, x2, Loop
Halt:
    halt                    # 模拟器扩展指令，不是标准 RISC-V 指令
```

程序对每个数组元素执行 `element += f2`。`x1` 指向当前元素，`x2` 是数组末尾的排他地址。测试程序默认处理两个元素。

## 模拟约定

- 地址为 32 位；数据内存按字节编址，每个 cell 为 8 位。`fld`/`fsd` 传输 8 个字节，要求 8 字节对齐。
- 指令使用枚举和结构化字段保存，不编码为机器码；为了体现取指 PC，按 4 字节的 RISC-V 指令地址步进。
- 内存内部把指令映射和数据字节映射分开保存，但共用 32 位模拟地址空间；代码和数据地址不能重叠。
- 整数寄存器为 32 个 32 位寄存器，`x0` 恒为 0；浮点寄存器为 32 个 64 位寄存器。
- `fadd.d` 使用 C++ `double` 运算；内存以小端字节顺序保存其 64 位表示。
- `Halt:` 是标签。模拟器增加了一条自定义 `halt` 指令，并在它到达 WB 时退休、停止模拟。
- `bne` 在 EX2 阶段解析。顺序取指路径上已进入 IF、ID1、ID2、EX1 的年轻指令会被冲刷；取指请求带 epoch，旧路径的迟到响应会丢弃。

## 全局事件队列

事件按 `(模拟时间, 阶段优先级, 插入序号)` 排序。同一模拟时刻先处理外部事件（包括内存请求到达和响应），再处理 CPU 时钟沿。因此响应恰好落在时钟沿时，CPU 能在该沿看到响应，行为不依赖事件先插入队列的顺序。

每个 CPU 时钟沿先统计上一周期中仍在等待的 MEM2 操作，再把响应邮箱中的内容应用到 IF 或 MEM2 槽，并完成到期的 EX1、EX2 工作。随后 CPU 从同一份流水线状态计算所有阶段的 `done`、`canAccept` 和 `willMove`：WB 的出口始终可用，其余阶段从 WB 向 IF 反向计算。ID2 的相关判断也纳入这份计划。所有可转移指令先写入 `next` 状态，再统一提交，因此阶段处理顺序不会改变同一时钟沿的结果。

指令进入某阶段后启动该阶段工作；零延迟工作在进入时即可完成，但只能在后续时钟沿转移。EX1 完成地址计算和 `addi`，EX2 完成 `fadd.d` 与 `bne` 比较。Load/Store 在 MEM1 发出一次带唯一 `requestId` 的请求，在 MEM2 等待响应。内存回调只校验并把响应放入 CPU 邮箱；若响应先于指令到达 MEM2，邮箱会暂存它，等 MEM2 消费。

ID2 每个时钟沿都会检查源寄存器：从 EX1 到 WB 找最近的较早写入者，最近生产者的结果无效时就停顿。EX1 开始工作时，再从 EX2 到 WB 选择有效旁路值覆盖 ID2 读出的寄存器快照。最近但未就绪的生产者会遮蔽更早的写入者，避免误用旧值。

## 流水线职责

| 阶段 | 工作 |
|---|---|
| IF | 按 PC 发起取指，并接收指令响应 |
| ID1 | 解码结构化指令，记录解码完成状态 |
| ID2 | 读取寄存器堆、确定源寄存器、检查 RAW 数据相关 |
| EX1 | 计算访存有效地址，执行 `addi` |
| EX2 | 执行 `fadd.d`，比较 `bne` 并生成分支结果 |
| MEM1 | 发起一次 Load/Store 请求 |
| MEM2 | 等待并接收对应的 Load/Store 响应 |
| WB | 更新整数或浮点寄存器并退休指令 |

模型采用弹性单槽级间寄存器。MEM2 等待响应时会产生背压；背压逐级传向更早阶段，直到遇到空槽或停住 IF。每个槽保存动态指令序号和 PC，因此同一个 `Loop` 地址在多次迭代中仍能区分不同动态实例。

## 从五级扩展

本分支从五级流水线版本继续演进，主要变化集中在阶段边界与依赖它们的控制逻辑：

- `ID` 拆成 `ID1` 解码和 `ID2` 读寄存器、检查冒险；
- `EX` 拆成 `EX1` 地址计算/整数加法和 `EX2` 浮点加法/分支比较；
- `MEM` 拆成 `MEM1` 发请求和 `MEM2` 等响应；
- `Stage::Count` 决定流水线槽位和转移计划数组长度，背压仍按 WB 到 IF 反向计算；
- 分支决策从 EX 移到 EX2，因此 taken branch 冲刷范围扩展到 IF..EX1。

扩展阶段时，需要同步调整该阶段的完成条件、进入阶段时启动的工作、响应归属、冒险/旁路搜索范围，以及分支冲刷边界。全局事件队列与统一提交 `next` 状态的机制保持不变。

## 延迟配置

```sh
./build/simulator
./build/simulator --elements 8 --addend 0.25
./build/simulator --elements 4 --cycle 3 --cpu-to-memory 1 --memory-to-cpu 2 --add 5
./build/simulator --trace-file build/loop-trace.log
```

参数单位为整数纳秒：

- `--elements N`：数组元素数，范围 1 至 10,000。
- `--addend X`：写入浮点寄存器 `f2` 的加数。
- `--cycle N`：CPU 时钟周期，必须大于零。
- `--cpu-to-memory N`：请求链路延迟。
- `--memory-to-cpu N`：响应链路延迟。
- `--add N`：`fadd.d` 的 EX2 和 `addi` 的 EX1 运算延迟。
- `--trace-file PATH`：详细事件和流水线轨迹输出路径，默认是当前目录下的 `simulation.log`。

默认时钟周期 2 ns，请求和响应链路各 2 ns，EX1/EX2 算术延迟 1 ns。它们是教学模型参数，不是特定处理器的测量值。

在 WSL 中执行：

`make` 将可执行文件、对象文件和依赖文件生成到 `build/`。`make test` 检查八级流水线结构、两元素循环、单元素不跳转退出、浮点结果、访存等待、RAW 停顿、分支冲刷，以及同时间外部事件先于 CPU 边沿的规则。运行 `./build/simulator` 时，终端显示配置、统计、最终数组结果，并在仿真过程中逐时刻显示 `PIPE` 流水线快照；其他逐事件细节写入 `simulation.log`。日志同样包含流水线快照；交互式终端支持颜色时，快照颜色也会写入日志，否则均为纯文本。用 `--trace-file PATH` 可更改日志路径。

## 当前范围

这是顺序、单发射的教学模型，没有缓存、分支预测、乱序执行或虚拟内存地址转换。内存服务时间为 0 ns，CPU/Memory 链路延迟分别建模；内存可并行接受事件请求，不模拟端口仲裁。IF 每次最多保留一个取指请求。指令以结构化对象存放，不模拟机器码译码。
